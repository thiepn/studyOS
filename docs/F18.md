## Changed functionality

- Server-side Calendar creation admission requires the actual owner session, an explicit confirmed request, a selected owned writable destination, a successful and nonfailed remote sync within six hours (reject future/malformed timestamps), and a nonempty proposal. Review checkbox alone is no longer authority.
- Editing selected Calendar sources invalidates the previous `last_sync_at` success **before** changing the selected set. A failed next sync cannot authorize writes against stale old-source free/busy data.
- Every selected source's entire paginated Calendar snapshot is fetched before mutating local Calendar event rows. An upstream fetch/page failure leaves the old local event snapshot in place and records sync failure; database write failures still may partially persist and are reported, not claimed atomic.
- Repeated Calendar page tokens and unbounded pagination fail closed; a Google event title containing “StudyOS” no longer impersonates StudyOS ownership without the private event marker.
- Setup shows a direct, explicitly nonauthoritative real-first-use acceptance drill: real semester → authentic source → independent attempt → Calendar evidence → cross-device/privacy verification.
- Regression tests cover the server admission boundary, stale/future/missing evidence, source invalidation ordering, complete-fetch ordering and marker-only ownership.
