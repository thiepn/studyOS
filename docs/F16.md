## F16 original-byte escrow verification
A new stand-alone **read-only** verifier `scripts/f16-source-custody.mjs`, CLI `scripts/audit-f16-source.mjs` and strict TS declaration assess *independently provided* files: **(i)** externally retained encrypted archive bytes, **(ii)** original prior-stable plaintext snapshot bytes in a trusted offline environment, **(iii)** externally restored snapshot bytes. The verifier reads and SHA256-checks the actual three files, byte-compares original and restored snapshots with constant-time comparison, checks basename traversal/symlink containment, rejects missing/oversized source files, and never executes a restore, writes data, decrypts or exposes source content. The source class is `synthetic` or *externally asserted* `external`: neither is accepted as original provenance proof on its own. An encrypted-archive file being hashed **does not prove valid authenticated encryption, key custody or restorability**.

Six mutually distinct, externally governed Ed25519 signer roles must attest **only HOLD**: `source_custodian`, `restore_witness`, `cross_owner_witness`, `staging_reviewer`, `release_reviewer`, `postrelease_reviewer`. All individual signatures bind the same SHA256 **commitment over the entire source-and-two-owner packet** (not just a mutable packet ID), and are checked against externally supplied, trusted, nonrevoked public roots. Two pseudonymous, distinct asserted-owner records must carry the exact original-source artifact digest and deny foreign-owner access; these are independently auditable assertions **not** actual two-account RLS acceptance without real supplied witness evidence.

Packet JSON contract:
```json
{
  "version":"studyos-f16-source-v1",
  "head":"<exact-git-SHA40>",
  "packetId":"independently-assigned-opaque-ID",
  "source":{"recordedAt":"2026-10-10T15:00:00Z","sourceClass":"external",
    "files":[
      {"kind":"encrypted_archive","path":"encrypted.bin","sha256":"<sha256>"},
      {"kind":"original_snapshot","path":"prior-original.bin","sha256":"<sha256>"},
      {"kind":"restored_snapshot","path":"restored-in-isolation.bin","sha256":"<sha256>"}
    ]},
  "ownerChecks":[
    {"ownerPseudonym":"owner-a","role":"owner","result":"allowed","evidenceSha256":"<one declared artifact SHA256>"},
    {"ownerPseudonym":"owner-b","role":"foreign","result":"denied","evidenceSha256":"<one declared artifact SHA256>"}
  ],
  "receipts":[{"role":"source_custodian","actorId":"opaque-external-ID",
    "keyId":"external-key-ID","head":"<exact-git-SHA40>",
    "packetId":"independently-assigned-opaque-ID","sourceCommitment":"<sha256>",
    "decision":"hold","issuedAt":"2026-10-10T15:00:00Z","signature":"<Ed25519-base64>"}]
}
```
Provide all six `receipts`. `sourceCommitment=SHA256(UTF8(JSON.stringify({version,head,packetId,source,ownerChecks})))`. Each signature is Ed25519 over UTF8(JSON.stringify(receipt without `signature`)). The six external trust roots contain `role`, `actorId`, `keyId`, `status:"trusted"`, `publicKeyPem`, `revokedKeyIds`. Synthetic fixture keys only test the verifier, never qualify original human authority.

Run in a separate, permissioned **offline** review environment:
```sh
node scripts/audit-f16-source.mjs \
  --packet /external-custody/f16-originals.json \
  --roots /independent-governance/six-trust-roots.json \
  --files /offline-original-source-directory \
  --head <exact-qualified-source-SHA>
```

The CLI does not call the F15 witness CLI automatically: its assessment **must** be paired by an external operator with an independently qualified F13→F14→F15 chain at the **same exact head**, not substituted for that chain.
