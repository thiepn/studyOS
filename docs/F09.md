## F09 implementation
- A source pipeline header and anchor navigation leads users from connected Drive discovery to processing, source-grounded candidate inspection/decision and searchable registered material. Course switcher uses active-semester roster; existing server RLS and `scopeCourseRecords` retain isolation.
- Source index uses native keyboard-friendly search and status/type filters, zero-result recovery, accessible result counts, declared-authority wording, unverified versus truly verified status, optional recorded source fingerprint and original Drive link. Declared authority is NOT a verified license or proof of integrity.
- Unresolved Drive intake can be searched and filtered; filename classifications remain labeled as unverified suggestions rather than operator approval. Manual registration remains separate.
- Candidate review now exposes complete submitted JSON to inspect before acceptance. Existing server validation's blocking-error check stays mandatory; acceptance requires deliberate local acknowledgement and is not independent signoff. Rejections collect a reason. No unapproved object publication.
- Manual source authority defaults to Unknown, rather than implicitly asserting official-course origin. Manual candidate submission no longer fabricates 90% extraction confidence; server validation still runs normally.
- Existing Drive account, Google OAuth consent, scan behavior, backend ingestion acceptance/rejection, Supabase RLS, user/session boundaries, offline attempt queue, scores, review eligibility and database are untouched.
- Editorial F04-F08 paper/ink UI, 44px targets, no gradients, responsive forms, forced-colors and reduced motion, native keyboard controls, live update messages and no screenshot golden replacement.
