# P24 — Exam Result Intake, Outcome Reconciliation & Retake/Completion Decisions

## Objective

P23 closes the operational exam boundary. P24 records the academic outcome that may arrive later and turns it into an explicit semester decision.

P24 answers:

> What actually happened, how does that outcome relate to the evidence StudyOS had before the exam, and should this course now close, pause, or enter a retake runway?

## Durable result state

P24 adds one dedicated table:

`study_exam_results`

This is intentionally separate from P9's `study_exam_simulations`.

P9 simulations are practice evidence.
P24 results are real university assessment outcomes.

Each row stores:

- course / semester / owner;
- attempt number;
- actual exam timestamp;
- provisional or official result status;
- outcome: passed / failed / absent / withdrawn;
- optional grade/mark text;
- optional score percentage;
- optional result source URL/note;
- the P17 readiness index/band and decision priority captured at intake;
- retake decision;
- optional future retake exam timestamp;
- recorded/updated timestamps.

There is one result row per user/course/attempt.

## Security

`study_exam_results` has owner-only RLS.

Authenticated permanent accounts may read/write only rows whose `user_id = auth.uid()`.

Anonymous writes are rejected.

The table also has composite owner foreign keys to the StudyOS course and semester.

## Atomic result write

P24 adds:

`study_record_exam_result(...)`

The RPC writes the result and applies any official structural course decision atomically.

It prevents:

- future exam timestamps being submitted as completed attempts;
- invalid outcome/status values;
- official → provisional downgrade;
- passed results carrying retake state;
- planned retakes without a future date;
- next exam dates on non-planned decisions.

## Provisional results

A provisional result is informational only.

It:

- does not deactivate the course;
- does not change `exam_at`;
- does not change course kind;
- does not trigger pass/retake structural state.

A provisional attempt may later be upgraded to official using the same attempt number.

An official result cannot be downgraded back to provisional.

## Official pass

An official pass:

- keeps the result history;
- sets `study_courses.active = false`;
- removes the course from active P17/P18/P22 planning;
- suppresses remaining retention/discretionary work;
- invokes P23 cleanup/reallocation best-effort.

P24 does not delete course evidence.

## Official non-pass

Failed, absent, or withdrawn official outcomes require one explicit retake decision.

### Decision pending

The course stays active as `course_kind = retake`, but `exam_at` is cleared.

P10 and the retention queue suppress discretionary work for the course until the decision is resolved.

Real commitments remain untouched.

### Retake planned

The course:

- remains active;
- becomes `course_kind = retake`;
- receives the supplied future `exam_at`.

From that point the existing system automatically takes over:

- P17 gets a new runway;
- P18 gives retakes their existing protection;
- P9/P22 reactivate as the exam approaches;
- P10/P11 remain the capacity/clock authorities.

No parallel retake scheduler is introduced.

### Retake declined

The result stays recorded, but the course is deactivated without being marked passed.

This represents an explicit decision to stop allocating StudyOS capacity to that course.

## Result-ready detection

A course appears in result intake only when:

- its configured exam has actually ended and no official result exists for that attempt; or
- the latest result for that configured attempt is provisional and can be upgraded; or
- the latest official non-pass has a pending retake decision.

A previously passed/closed course does not repeatedly reappear merely because its old `exam_at` remains in the past.

## P17 reconciliation

P24 intentionally does **not** treat the P17 readiness index as a predicted exam percentage or pass probability.

The stored snapshot is compared only directionally.

Possible labels:

- `provisional`
- `insufficient_evidence`
- `aligned`
- `positive_surprise`
- `negative_surprise`
- `mixed`

Examples:

- fragile/at-risk readiness + pass → positive directional surprise;
- target-ready/strong readiness + non-pass → negative directional surprise;
- weak evidence → no outcome judgment.

P24 never computes:

`exam grade - readiness index`

and never calls that forecast error.

## Snapshot preservation

When a result is first recorded, P24 captures:

- P17 readiness index;
- P17 readiness band;
- P17 decision priority.

On later updates to the same attempt, an existing snapshot is preserved rather than replaced by a newer moving forecast.

This makes historical reconciliation stable.

## P23 cleanup relationship

Official result recording is the primary academic write.

P23 cleanup/reallocation runs afterward as a best-effort operational follow-up.

Therefore a Google Calendar failure cannot prevent the actual exam result from being saved.

Cleanup warnings are surfaced to the user.

## Planning gates

P24 adds a latest-official-result gate to P10 and retention.

Discretionary planning is suppressed for:

- passed courses;
- non-passing courses with retake decision pending;
- non-passing courses whose retake was declined.

A planned retake is not suppressed because it has a new authoritative future exam date.

Explicit P10 commitments are never removed by this gate.

## UI

New route:

`/exam-results`

It provides:

- semester outcome counts;
- result intake/update form;
- official/provisional status;
- pass/fail/absent/withdrawn outcome;
- optional grade text and percentage;
- retake decision;
- future retake date;
- source URL/note;
- stored P17 snapshot;
- directional reconciliation;
- structural course state;
- complete attempt history.

Today shows a compact P24 card when:

- an ended exam is ready for outcome intake; or
- a failed/absent/withdrawn course is waiting for a retake decision.

Primary navigation includes **Results**.

## Persistence authority

P24 is the first phase since P19 that genuinely requires new durable state.

That state is limited to actual academic outcomes.

P24 does not persist:

- speculative predictions;
- derived reconciliation labels;
- P17 forecast accuracy scores;
- duplicate retake plans;
- post-exam workflow state already represented elsewhere.

## Guardrails

P24 must never:

- infer an actual grade from P17;
- call readiness a pass probability;
- close a course from a provisional result;
- schedule a retake without an explicit future date;
- resume a pending-retake course as normal coursework;
- erase prior attempts when a retake is scheduled;
- make calendar cleanup a prerequisite for saving a real result;
- delete course evidence on completion;
- treat “declined retake” as “passed.”

## Next phase

**P25 — Semester Completion Ledger, Credit/Pass Progress & End-of-Semester Review**

P25 should aggregate official P24 outcomes into the semester-level completion picture: passed credits, unresolved/retake credits, completed vs unfinished courses, outcome history, and an end-of-semester retrospective that evaluates StudyOS decisions without turning readiness into fake predictive accuracy.
