# P22 — Exam-Period Command Center, Multi-Exam Conflict Resolution & Final-Runway Scheduling

## Objective

P9 already knows what each course should do next for exam preparation.

P22 solves a different problem:

> What happens when several P9 exam strategies compete for the same limited days, energy and calendar capacity?

P22 therefore coordinates **between exams** without becoming another exam-strategy engine.

## Authority hierarchy

P22 may:

- rank competing exam runways;
- add bounded cross-exam priority pressure to P10;
- temporarily withhold a heavy P9 action when exam-day/fatigue constraints make it unsafe to place today;
- preview where each course's current P9 action can fit in the next seven days;
- expose impossible conflicts.

P22 must not:

- replace a P9 action with another method;
- change the action title/link/duration;
- invent the next P9 action after the current one;
- increase P10 daily capacity;
- move P11 calendar events by itself;
- change P17 readiness;
- change P18/P19 weekly capacity;
- weaken retention or real commitments to manufacture exam time.

## Activation

A course enters P22 when:

- P9 operating mode is `transition` or `exam`;
- `days_to_exam >= 0`;
- P9 has an actionable next step other than `maintain_blueprint`.

P22 supports single-exam visibility, but conflict modes become meaningful when multiple courses overlap.

Command levels:

- `inactive`
- `single_exam`
- `multi_exam`
- `compressed_conflict`
- `critical_conflict`

Two or more exams within 21 days create a compressed conflict.
Two or more within 7 days create a critical conflict.

## Cross-exam command score

Each active exam gets a bounded 0–100 command score from:

- exam urgency;
- readiness gap;
- existing P17 decision priority;
- fragile/at-risk readiness band;
- declining trajectory;
- weak/missing verified simulation evidence.

This score only coordinates competing P9 actions.

It is not a new readiness score and does not feed back into P17.

## P10 integration

P22 produces a Today directive for each active exam course.

When multiple exams overlap, P22 may add exam-only priority pressure:

- rank 1: strongest boost;
- rank 2: smaller boost;
- rank 3+: progressively smaller boosts;
- ≤3-day runways receive a small additional urgency boost.

The adjustment is added only to `exam_strategy` candidates.

P22 never modifies:

- commitments;
- retention review;
- ordinary coursework;
- P14 drift repair;
- P19 weekly-envelope candidates.

Single-exam mode adds no cross-exam priority adjustment because there is no conflict to resolve.

## Heavy-work protection

P22 classifies full timed papers as heavy exam work.
Long repair/mixed actions may also be treated as heavy when their current P9 duration is at least 75 minutes.

### One heavy exam slot per day

During a cross-exam collision, at most one heavy exam action may own Today.

The highest-ranked heavy action only claims the slot if it can actually fit today's protected exam capacity.
A higher-ranked action that cannot fit is not allowed to block a smaller heavy action that can.

### Same-course simulation cooldown

A new timed simulation is withheld from Today when the previous simulation finished within roughly 36 hours.

The seven-day preview shifts it to a later date instead of pretending it is available immediately.

### Final 24 hours

P22 will not place a heavy exam action inside the final 24-hour runway.

The underlying P9 action remains unchanged and visible as a conflict.
P22 does not silently substitute a lighter method.

### Exam day

When `days_to_exam = 0`, P22 schedules no additional P9 preparation into the exam day.

The exam itself owns that day's exam load.

## Seven-day runway preview

The new command center builds a seven-day preview for the **current P9 action only**.

This is intentionally not a seven-day strategy script.

After an action is completed:

1. P9 recalculates the course strategy;
2. P22 receives the new P9 action;
3. the runway is rebuilt.

For each day, P22 uses an exam-specific upper bound after protecting:

- P10 hard daily capacity;
- P10 retention reserve;
- real open commitments due that day;
- overdue commitments on Today;
- P11 calendar free-time limits.

The current day uses P11's remaining windows after the current clock rather than the full elapsed day.

The preview then greedily places current P9 actions by command priority.

Heavy exam actions are separated by at least one clear calendar day when the runway allows.

If an action cannot fit before its exam while preserving those boundaries, P22 leaves it unplaced and exposes a conflict.

The preview remains an **upper bound** for exam preparation. P10/P19 can still allocate other legitimate discretionary work inside the same overall daily budget.

## Conflict types

P22 exposes:

- `exam_today`
- `final_day_heavy`
- `simulation_cooldown`
- `cross_exam_heavy`
- `capacity`

A conflict is explanatory state, not a replacement method.

## P11 runway improvement

P21 introduced arbitrary bounded calendar ranges.

P22 hardens that helper:

- if the requested runway includes Today, Today's free windows are clipped after the current time;
- future days retain full configured planning windows.

This also improves Monday handoff accuracy in P21.

## UI

New route:

`/exam-command`

It shows:

- command level;
- urgent/compressed exam count;
- P10 budget and protected retention;
- per-exam command rank;
- P17 readiness/trajectory context;
- current P9 action and duration;
- exam date derived from P9 runway;
- Today eligibility;
- conflict reason;
- P10 priority adjustment;
- whether the exam action was selected in today's P10 plan;
- seven-day protected action-placement preview;
- heavy-work guardrails.

Today receives a compact P22 card whenever the command center is active.

Primary navigation includes **Exam Command**.

## Persistence

P22 adds no persistence.

It derives state from:

- P9 `study_exam_strategy`;
- P17 forecast;
- P10 current capacity and commitments;
- P11 calendar runway;
- existing P9 simulation history.

No table, migration, RPC or RLS policy is added.

## Current cold-start behavior

If `study_exam_strategy` has no rows yet, the command center remains inactive.

This is expected before exam dates/P9 evidence are configured.

P22 does not fabricate an exam runway from course names or semester dates.

## Guardrails

P22 must never:

- interpret command rank as predicted exam score;
- change P9's method;
- schedule two heavy exam actions into the same Today slot;
- schedule a full timed simulation during its recovery cooldown;
- schedule heavy exam work inside the final 24 hours;
- schedule extra preparation on exam day;
- steal mandatory commitment or retention capacity;
- exceed P10/P11 capacity;
- create future P9 actions that do not yet exist;
- persist speculative seven-day action sequences.
