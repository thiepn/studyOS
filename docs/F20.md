## Demonstrated defects and source repairs

- **Cross-account offline fallback:** An in-flight attempt or session request could fail after user A signed out and user B signed in; it would previously enqueue A's content with *B's* owner ID. Capture the session owner before POST and require that same original owner both for fallback queue storage and successful-reply confirmation. On ambiguity do not claim receipt or retry another account; inspect original owner's history.
- **Cross-account session ID collision:** Adding session A previously removed a pending record with same sessionId belonging to B. New collision handling updates only the matching owner+ID and retains foreign and legacy-unowned records.
- **Silent local data loss:** Both attempt and session queues previously clipped to 100/20 records, potentially evicting another owner's records. Full or malformed queues now refuse new writes without clearing existing evidence; no queue capacity or clipboard claim substitutes for encrypted original-byte backup.
- **Account switching:** Explicit permanent-account check added to the same-origin request that authorizes Google identity switching, supplementing downstream independent server authorization.
- **Static DB contract audit:** `node scripts/audit-f20-db-contract.mjs` checks committed SQL contracts for owner-scoped initial semester, dynamic readiness snapshot, Calendar refresh-token RLS denial, and governed historical priors. **This is a static source audit, not execution against Supabase or proof of deployed migration compatibility.**
