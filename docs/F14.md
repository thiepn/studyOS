## Changed real application paths
- `offline-attempts.ts` and `offline-sessions.ts`: check original owner **immediately before each queued API POST** and **again after acknowledgment before dropping a queue item**. An account change, unknown/legacy queue record, or failed identity lookup stops replay and retains the item for same-account reconciliation. The original idempotent attempts API, response validation and server RLS remain authoritative.
- Attempt deletion is restricted to the matching owner+client request ID, reducing the risk of removing another owner's same-ID record. Queued sessions remain keyed by original session ID and owner.
- Browser `storage` events refresh Account Recovery and sync status after another tab changes the queue. The auto sync bridge also checks owner identity between the three flush phases.
- Pure async owner guard and adversarial tests simulate account rotation, lost authentication and foreign legacy records. Actual network sequencing is still bounded by the server's owner checks, not a promise of atomic multi-tab delivery.
- No logout, OAuth, Supabase schema, course, planner, or learning progression contracts changed.

## Independently verifiable reviewer intake
- `scripts/f14-evidence-review.mjs` and `scripts/audit-f14-review.mjs` reconcile an **original F13 signed witness packet and artifact bytes** with a **separately signed reviewer report** and **custodian-signed, chained, chronological signer activation/revocation events**, all bound to one exact 40-character source SHA and packet digest.
- Source artifacts are read from the provided offline folder using F13's path/symlink/integrity protections; no source secrets or photo content are serialized into output. Review cases must refer to a matching witnessed artifact hash and a passed witness case.
- Separate witness, reviewer, operator and custodian actors; reviewer/custodian external trust roots; revoked key exclusion; no reactivation of a revoked key; monotonic event timestamps; duplicate/malformed/unsigned case rejection.
- Only an independently supplied `originKind:"external"` **label** plus complete signed scenario reviews yields `ready_for_owner_review`. Even this is **not proof** of independently controlled physical devices/people. The reviewer report may say only `hold` or `refer_to_owner`.
- The output **always** has `releaseAllowed:false` and `ownerDecision:"OPEN"`. Real source licenses, personal privacy and accessibility review authority are never inferred from a signature, ZIP hash or test result.

Run read-only on an independently controlled machine with externally provided files:

```sh
node scripts/audit-f14-review.mjs \
  --packet /witness/packet.json --witness-root /custody/witness-root.json \
  --review /reviewer/review.json --reviewer-root /custody/reviewer-root.json \
  --custody /custody/chronology.json --custodian-root /custody/custodian-root.json \
  --files /witness/original-files --head <EXACT_SOURCE_SHA>
```

Required reviewer fields: `version:"studyos-f14-review-v1"`, `head`, `packetSha256`, `reviewerId`, `reviewKeyId`, `reviewedAt`, `decision:"hold"|"refer_to_owner"`, `cases:[{id,result:"observed"|"blocked"|"unobserved",artifactSha256}]`, base64 Ed25519 `signature` on JSON-without-signature.

Custody ledger: `version:"studyos-f14-custody-v1"`, `head`, `packetSha256`, `custodianId`, `custodianKeyId`, `events`, `finalHash`. Each `event` has `sequence`, `previousHash`, `action:"activate"|"revoke"`, `role:"witness"|"reviewer"`, `keyId`, `custodianId`, `occurredAt`, `sha256`, `signature`. Event digest/signature covers JSON excluding `sha256` and `signature`. Root files for reviewer/custodian: `status:"trusted"`, `role`, `actorId`, `keyId`, `publicKeyPem`, `revokedKeyIds`.
