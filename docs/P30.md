# P30 — StudyOS Visual Identity

## Objective

P30 gives StudyOS a durable product identity without changing the P1–P29 study engine.

The interface should feel like opening an academic planner, workbook, and course binder—not a SaaS analytics dashboard.

## Visual principles

1. **Paper over cards**
   - warm paper is the base surface;
   - information is separated primarily by rules, margins, and hierarchy;
   - boxes are used only where a bounded object genuinely needs one.

2. **Ink over decoration**
   - near-black is the primary structural color;
   - color communicates course identity, state, or exception;
   - no decorative gradients, glow, glass, or AI-style visual effects.

3. **Academic typography**
   - system sans-serif remains the control/navigation face;
   - Georgia-style serif display text is reserved for page titles, course titles, study prompts, and editorial section headings;
   - page titles remain compact rather than becoming landing-page heroes.

4. **Course spines**
   - every stable course key maps deterministically to one of six muted course tones;
   - the same stable key receives the same visual family whenever it appears;
   - color is restrained to spines, rules, markers, and selected academic context rather than filling entire pages.

5. **Focus over instrumentation**
   - the active study question is the visual center of Study mode;
   - evidence controls remain accessible without competing with the question;
   - configuration and system controls recede behind disclosures where possible.

6. **Responsive continuity**
   - desktop and mobile use the same visual grammar;
   - mobile keeps the P29 bottom navigation;
   - course-spine identity compresses rather than disappearing except when space is genuinely too narrow.

## Core surfaces

### Today

Today keeps the P29 linear execution model:

- compact date/status context;
- one dominant **Now** action;
- ordered next actions;
- exceptional signals only;
- schedule/capacity controls remain secondary drawers.

P30 changes typography, rules, control geometry, paper tone, and hierarchy without changing planning authority.

### Study

The review workspace becomes a paper-solving surface:

- restrained top line with question/time context;
- a paper sheet with an academic margin rule;
- serif question text;
- high-contrast answer area;
- hints, rubric, grading, confidence, and error classification remain subordinate;
- no analytics panels surround the active question.

### Courses

The course index becomes a binder ledger:

- each course has a stable visual spine;
- course title, state, week strip, and action share one horizontal academic row;
- teaching weeks appear as a compact status strip rather than floating pills.

Course detail carries the same spine identity into:

- course header;
- master map;
- exam intelligence;
- weekly workflow.

Configuration is moved into a secondary **Course settings** disclosure.

### Progress

Progress becomes an evidence ledger:

- global semester summaries use ruled sections instead of dashboard cards;
- each course inherits its course spine;
- diagnostics use compact evidence bands;
- deeper drift/intervention/transfer evidence remains available but visually subordinate.

## Course identity contract

`src/lib/study/course-visual.ts` is the only course-color assignment helper.

- identity is based on `stable_key`, not display name;
- six muted tones are available;
- no learning or scheduling behavior depends on the tone;
- changing a display name cannot change the course identity;
- course tones are decorative/contextual only and never encode risk or mastery.

## Geometry

- primary radius: 2–3 px;
- buttons and fields are tool-like, not pill-shaped;
- status badges may use compact rectangular outlines;
- major page sections favor top/bottom rules;
- box shadows are rare and reserved for the active paper-solving surface or floating navigation menu.

## Color

Base:
- paper: warm off-white;
- sheet: near-white;
- ink: near-black;
- muted: warm gray;
- institutional accent: desaturated green.

Course palette:
- teal/green;
- muted violet;
- warm brown;
- slate blue;
- ochre;
- muted red.

Risk/status colors remain semantic and separate from course identity.

## Accessibility constraints preserved

P30 must preserve:

- visible keyboard focus;
- semantic buttons/links/forms;
- sufficient text contrast;
- reduced-motion handling already present;
- mobile touch targets;
- no meaning conveyed by course color alone.

A dedicated accessibility qualification remains P35.

## Non-goals

P30 does not:

- change navigation architecture;
- redesign the five core workflows structurally beyond small presentation changes;
- change scheduling or evidence logic;
- introduce arbitrary user theming;
- add gamification;
- add an AI assistant surface;
- create a generic component-library dashboard.

## Qualification

P30 is complete when:

1. one visual token system governs the product;
2. Today, Study, Courses, Course detail, and Progress visibly belong to one product;
3. stable course identity appears consistently across Courses/Progress/Course detail;
4. configuration no longer visually dominates Course detail;
5. generic large-radius SaaS cards and pill controls are substantially reduced;
6. mobile retains the same visual identity;
7. behavior tests pass;
8. TypeScript passes;
9. the Next.js production build passes.

## Next phase

**P31 — Core Experience Redesign**

P31 should now refine the interaction architecture of the five core experiences—Today, Study, Courses, Progress, and More—using the P30 visual language as a fixed foundation rather than redesigning the visual system again.
