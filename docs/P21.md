# P21 — Closed-Loop Weekly Review, Next-Week Handoff & Semester Adaptation

## Objective

P21 closes the week-to-week control loop created by P17–P20.

It answers:

> What happened in the week that just ran, what genuinely survives into the next week, what should change because of new evidence, and what full-week P19 commitment should replace the expired envelope?

The loop is:

```text
P17 current semester evidence
→ P18 weekly allocation
→ P19 committed execution
→ P20 allocation calibration
→ P21 closeout + handoff
→ refreshed P18/P19 week
```

## No study-time debt

P19 course envelopes are planning intent for one bounded calendar week.

At week end:

- completed/credited minutes become evidence;
- over-completion remains evidence;
- unfinished course-envelope minutes **expire**;
- those missing minutes are never copied into next week.

The next P18 allocation is recomputed from current evidence instead.

This prevents a bad week from creating an ever-growing backlog of artificial “debt minutes.”

## Real obligations are different

Open P10 commitments are real assignments/deadlines.

P21 does not copy or recreate them.

An unresolved commitment:

- keeps its existing ID;
- keeps its original due date;
- keeps its estimate/priority;
- remains open in P10;
- is reserved in the next-week mandatory envelope while it remains unresolved.

Therefore:

> study-envelope minutes expire; real obligations persist.

## Review window

P21 targets a Monday→Sunday operating week.

- On **Monday**, the target week is the current Monday→Sunday.
- On Tuesday–Saturday, P21 previews the upcoming Monday→Sunday.
- On **Sunday**, P21 previews the upcoming week, but a prior P19 week must finish and be explicitly closed before a normal handoff commitment can occur.

Cold-start users with no prior P19 week may commit without a closeout.

## Explicit weekly closeout

P19 already had the durable status values:

- `active`
- `completed`
- `cancelled`

P21 gives `completed` its operational meaning.

A prior weekly plan can be closed only after its Sunday has ended.

Closing the review:

- changes only the plan status to `completed`;
- does not rewrite allocations;
- does not erase missed work;
- does not fabricate completion evidence;
- does not change P20 analytics.

The complete review remains reproducible from the preserved P19 plan, allocations, sessions and workflow evidence.

No new review table is needed.

## Week review

For the previous P19 week, P21 reconstructs execution with the exact P19 runtime.

Per course it shows:

- final target minutes;
- credited minutes;
- adherence;
- expired envelope minutes;
- overage;
- original/final protection-floor sacrifice;
- readiness at the prior P19 snapshot;
- current P17 readiness;
- readiness change;
- current P20 floor adjustment.

The review total can exceed 100% because real credited work above an envelope is intentionally preserved.

## Calendar handoff runway

P11 previously exposed only a rolling today+6-day runway.

P21 adds an arbitrary bounded calendar-runway reader so StudyOS can evaluate the actual next Monday→Sunday window.

The handoff runway uses:

- selected Study Calendar sources;
- P11 day-start/day-end settings;
- event buffers;
- weekend setting;
- cached busy events;
- open commitments due in the target week.

The helper supports up to 21 days but P21 uses seven.

If Calendar is disconnected, P10's configured weekly ceiling remains authoritative.

If Calendar is connected, next-week capacity is capped by actual Monday→Sunday P11 free time.

Stale Calendar state is surfaced before commitment.

## Mandatory next-week reserve

P21 reserves two groups:

1. open commitments whose original due date is before the target Monday;
2. open commitments due during the target Monday→Sunday week.

They are de-duplicated by commitment ID.

A mandatory-work deficit blocks next-week commitment.

## Semester adaptation

P21 does not mechanically repeat the previous P18 objective.

It chooses a recommended objective from current evidence:

### Exam period

Selected first when an active course has:

- urgent/compressed runway; and
- material P17 decision priority.

### Protect passes

Selected when:

- at least one active course is `at_risk` or `fragile`; or
- the previous week sacrificed a course below its protection floor.

### Target 80+

Selected when pass protection is stable but at least one scored active course is below the 80+ readiness target.

### Balanced

Used when none of the exception states dominate.

The user may still choose another P18 objective at commitment time.

## P20 capacity adaptation

P20's whole-week capacity signal remains advisory.

P21 may automatically test **less** weekly course capacity when P20 has enough evidence for `commitment_too_high`.

For that conservative trial:

- mandatory work stays protected;
- the normal retention reserve stays protected;
- only the discretionary course-work budget is reduced by roughly 10%;
- P10 daily settings are not changed.

A `commitment_too_low` signal never expands P21 beyond the current P10/P11 ceiling. It is shown as advice only.

## P20 floor adaptation

All next-week P18/P19 allocations use the current bounded P20 protection-floor corrections.

The corrections remain:

- 15-minute steps;
- maximum ±30 minutes/course;
- evidence-gated by P20.

P21 does not create another calibration layer.

## Next-week commitment

P21 persists the selected target week directly into the existing P19 tables:

- `study_week_plans`
- `study_week_allocations`

The handoff snapshot records:

- previous plan ID;
- recommended objective/reason;
- current P20 capacity signal;
- current P20 floor-adjustment map;
- expired previous-envelope minutes;
- unresolved carryover commitment IDs;
- current P17 course readiness/priority;
- new P18 allocations.

The new plan remains ordinary P19 state.

When Monday arrives, the existing P19 runtime automatically sees it as the active weekly envelope.

## Close-before-commit invariant

If a prior P19 week exists:

1. let its Sunday finish;
2. inspect the P21 review;
3. explicitly close it;
4. P20/P17 evidence is refreshed;
5. commit the next Monday→Sunday week.

This prevents the next weekly plan from being locked against an unfinished predecessor.

## Persistence

P21 adds no table, view, RPC or RLS policy.

It reuses:

- P19 plan status for explicit closeout;
- P19 plan/allocation persistence for the next week;
- P19 execution evidence;
- P20 derived calibration;
- P17 current forecast;
- P11 calendar/event cache;
- P10 commitments.

## Authority boundaries

P21 may:

- close an ended P19 plan;
- recommend a next-week objective;
- recommend a bounded lower weekly trial when P20 supports it;
- commit a new P19 week.

P21 must never:

- carry unfinished course minutes forward as debt;
- duplicate open commitments;
- move an original deadline merely to make planning easier;
- close a week before it actually ends;
- commit a successor while an existing prior week still requires closeout;
- exceed the P10/P11 feasible ceiling;
- auto-increase capacity from a P20 `commitment_too_low` signal;
- override P9 exam-strategy authority;
- rewrite P17 readiness;
- alter P10 daily capacity;
- reinterpret the P20 calibration model.
