# P36 — Academic Workflow Qualification and Integrity Repairs

## Scope and evidence

This phase tests a representative academic lifecycle from lecture notes and week-numbered exercise sheets through independent practice, source-grounded grading, mistake repair, and cumulative checkpoint. It uses **synthetic, mathematically meaningful fixtures** for the third-semester courses Differentialgleichungen, Stochastik, Theoretische Informatik, and Algorithmische Mathematik und Programmieren. It does **not** claim to have ingested the student's actual semester uploads, driven a real web browser, or checked a live private deployment.

The study experience remains a paper/ink workspace. There is no new dashboard, AI correctness score, data migration, or added third-party dependency.

## Findings resolved

### 1. Dead practice links
**Before:** A binder week containing recorded skills could offer practice even if every approved question was too long for the 35-minute teaching-week window, or no active approved questions existed. That led to an empty practice route.

**Now:** The course workflow reads the active semester's skill-week anchors and active questions. The binder shows:
- Actual number of practice questions that fit its 35-minute window.
- Whether the learner can work on questions for that week right now.
- The count of questions without an attached rubric; learners must use an official/verified source for positive self-grading.
- A direct link to material processing if there is no fitting question, rather than a dead practice action.

Counts are scoped to the requested course and week. No week is marked ready merely because a skill exists.

### 2. Session budget rejected usable problems
**Before:** Both standard review and checkpoints ranked a question first, then discarded it if it exceeded the remaining time, even when a shorter alternative for the same skill existed.

**Now:** Each queue selects the highest-ranked **fitting** active question for the target skill. A 45-minute DGL proof cannot hide an available 12-minute derivation in a 35-minute review. If no usable problem exists, the queue correctly stays empty; the system does not invent an exercise or overrun the budget.

### 3. Hint-assisted work qualified for a closed-book checkpoint
**Before:** The server accepted any attempt except `solution_exposed` to certify a weekly checkpoint. A hint-assisted answer could therefore satisfy an advertised independent checkpoint.

**Now:** Server completion requires at least one saved attempt with `independence = independent` in a completed, course/week-tagged checkpoint session. **An incorrect independent attempt counts as completion but not as mastery.** Hint-assisted and unsynchronized attempts are not sufficient. The learner-facing guidance matches the server policy.

### 4. Draft recovery could cross week or finding context
**Before:** A saved in-progress review draft was keyed by course, session type, and question content. Two different weeks or repairs with the same selected questions could accidentally restore the wrong unfinished session and its checkpoint linkage.

**Now:** Draft identity additionally includes the originating return route (including teaching-week anchor) and the exact completion note/finding token. Unfinished week-2 work cannot appear in week 3; repair for one finding cannot be resumed as another. This change intentionally invalidates older draft keys when the workflow context differs.

### 5. Real Stochastik expression escaped rendering
Added support for `\\mid` and `\\nmid` notation, e.g. `P(A\\mid B)`, to native MathML. Unsupported TeX remains visible as text; no mathematical correctness checking is claimed.

## Automated qualification scenarios

- **Differentialgleichungen:** A short derivation is selected instead of an oversized proof; working+conclusion survives the current answer model; rubric hidden until answer and confidence are locked; a failed method produces classified repair evidence.
- **Stochastik:** Conditional probability notation renders; no attached answer key means a positive grade needs independently verified source confirmation.
- **Theoretische Informatik:** An induction or proof task exceeding the practice window does not advertise a playable set; hint-assisted partial proof cannot certify a closed-book checkpoint.
- **Algorithmische Mathematik und Programmieren:** Withdrawn/inactive programming questions are excluded; a prior bug attempt does not count as a later independent repair success.
- **Course-week boundary:** Solution links remain hidden until a recorded independent sheet attempt; a checkpoint session must end and match the precise week.
- **Cross-mode navigation:** Week-specific practice and mistake-specific repair drafts cannot restore against another week or finding.

Tests are deterministic and run in the repository's existing Node regression suite. TypeScript and Next.js production build are mandatory gates.

## Explicit unverified work

1. Real student's lecture files, official exercise sheets, and official solution PDFs have **not** been uploaded or used for this phase.
2. The connected Vercel account's project search did **not** return a StudyOS deployment. No deployed application or custom-domain URL was verified.
3. Actual Android phone, iPad/tablet, keyboard, browser refresh, screen-reader, and offline-reconnect behavior **have not** been exercised by a graphical browser. CSS changes from P35 and P36 still need real-device evidence.
4. Server integration and Supabase RLS/RPC authorization are not exhaustively tested against production user records by the pure unit tests.

### Device acceptance script for a later live verification
On a test account in the active semester, register a lecture, exercise sheet and official solution for a course week. Approve questions and verify the binder's ready count. Open week practice and solve a short item independently, then grade it against a verified source. Record a finding and run the exact-skill repair before resolving. Leave a second question unfinished, reload in the same tab, and ensure its original week and answer reveal state are preserved. Try a hint in an independent checkpoint, verify it does **not** certify completion, then complete an independent attempt. Repeat on Android, a tablet, and keyboard-only desktop; take screenshots and capture actual network/offline results.

## Release criterion
Merge only after a clean lockfile install, all behavior tests, typecheck and production build. This is **code-qualified**, not a claim of production/live-device acceptance.
