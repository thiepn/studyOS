## Actual implementation
1. **Active-work context** — the review workspace now exposes three meaningful stages (Solve, Compare, Record), the current question, active minutes versus advisory target, typed/paper working surface and context for retrieving, coursework, cumulative checkpoints and targeted repair.
2. **Honest evidence state** — labels reflect existing `independence` levels only: independent without hints, one/two hints, or solution exposed before answer lock (zero mastery credit). Confidence remains pre-reveal; the original `canRevealRubric`, `escalateIndependence`, `assessmentReady`, `assessmentSourceVerified`, hint gates, attempt recording and grading are unchanged.
3. **Keyboard and mathematical input** — a direct Focus working editor button uses the existing text-area ref. Existing Ctrl/Command+Enter locking, proof outline navigation, plain-text and TeX/MathML math rendering remain. F04's academic paper-and-ink layout, 44px controls, forced-colors and reduced-motion support extend to the new UI.
4. **Persistence and privacy** — per-tab draft restoration, queue-bound fingerprinting, locked state after rubric reveal, account-bound offline attempt queue, session finish and safe recovery remain unchanged. The workspace explicitly distinguishes in-tab drafts from queued attempts awaiting sync. A completed session shows the real outcomes and queued states per question, never projecting a queued item as a confirmed server save.
5. **Timed exam navigation** — question buttons announce question identity and whether an answer or grade exists; `aria-current=step` identifies the active question. The existing live countdown is exposed as a timer without per-second live announcements. Timed-exam submission, deadline, scoring and verified-rubric gates are untouched.
