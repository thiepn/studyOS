# P33 — Mathematical Work and Verifiable Skill Repair

## Implemented

P33 makes the review and course binder useful as an actual mathematics study workflow. It is not another planner, dashboard, or chat interface.

### Work before grading
- Typed practice has separate **working/proof steps** and **conclusion/claim** areas, plus a compact Unicode notation bar.
- Both areas are serialized into the existing locked response text, capped by the existing attempt pipeline, and preserved with the same mastery, offline queue, hint/exposure and confidence-before-reveal policies.
- Paper mode continues to work without pretending StudyOS has photographed or graded handwriting.
- The editor deliberately does **not** claim to auto-evaluate, typeset, or symbolically prove mathematical work.

### Exact-skill repairs
- `/practice?mode=repair&course=<courseId>&skill=<skillId>&finding=<optionalFindingId>` validates that the active semester owns the course, skill and (if specified) matching finding.
- Builds a bounded independent practice set only for the mapped skill (maximum two questions); favors exam/transfer/execution evidence, then rubric availability.
- Displays the original discrepancy and its exercise sheet without exposing the linked official solution before independent work.
- An empty verified question set is an honest empty state, not a fake completed repair.

### Source-linked discrepancy register
- Course week discrepancy entry may attach the exact exercise and official solution resource.
- Server verifies the source is active, in the same course and week, and of the correct resource type. Skill references must be active and belong to the same course.
- Existing duplicate records can be dismissed with a written reason (minimum 10 characters); this is distinct from crediting a repair.
- Resolving a mapped finding now requires a saved attempt after the finding was created, tied to the exact skill, self-rated **correct**, and marked **independent** (not hint-assisted or solution-exposed).
- Incomplete/offline-only attempts do not satisfy this rule until they sync.
- Resolution records an identifying attempt reference in the existing resolution note for traceability.
- Unmapped findings may be dismissed with a reason; they cannot count as verified repairs until mapped. Existing unmapped findings have no edit/mapping action in this slice.
- The server returns 409 for missing evidence; a frontend click can no longer unilaterally declare repair success.

### Limits and risks
- A correct rating is **self-assessed** against an attached or externally verified rubric. StudyOS does not independently verify the mathematical validity of a proof.
- Source visibility changes are UI-level disclosure, not Google Drive permission changes.
- No schema migration is required. There is one authoritative source of session attempts and one authoritative findings ledger.
- Existing exam, scheduled review, cumulative checkpoint, and course plan workflows remain unchanged.
- Browser/device live QA is still needed, especially typed notation, paper mode, and disconnected→reconnected repair flows.
- Pending next steps: learner-grade spaced repair scheduling, explicit re-mapping of older unmapped findings, and actual mobile/device proof workflow observations.
