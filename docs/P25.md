# P25 — Semester Completion Ledger, Credit/Pass Progress & End-of-Semester Review

## Objective

P24 records actual exam outcomes. P25 aggregates those outcomes into one semester-level academic ledger without inventing a second source of truth.

P25 answers:

> How much of the semester is actually complete, which credits are passed or still open, what happened across attempts, and what should StudyOS learn from the semester?

## Persistence

P25 adds **no new table, view, RPC, enum, trigger, or durable state**.

The authoritative sources remain:

- `study_exam_results` — P24 actual outcomes and attempt history;
- `study_courses` — configured course metadata and credits;
- P19/P20 weekly plans and execution evidence — workload calibration history.

The P25 ledger is derived on read.

This prevents a semester-summary row from drifting away from the underlying results.

## Course completion states

Every configured course is placed into exactly one state:

- `passed`
- `retake_planned`
- `retake_pending`
- `closed_without_pass`
- `provisional_result`
- `awaiting_result`
- `ongoing`
- `inactive_unresolved`

### Retake boundary

P25 uses P23's exam-boundary logic rather than checking calendar dates by itself.

A planned retake whose new exam has actually finished becomes `awaiting_result` until a P24 result is recorded.

A newer provisional retake result takes precedence over the prior official failure.

## Credit accounting

Credits are counted once per course, never once per attempt.

P25 reports:

- configured credits;
- passed credits;
- planned-retake credits;
- unresolved/active credits;
- credits closed without pass;
- pass-credit percentage.

Courses with no configured credits are excluded from the numeric denominator and surfaced explicitly.

Therefore a displayed percentage is never silently based on invented credit values.

## Attempt accounting

P25 preserves the full P24 attempt history.

It reports:

- official attempts;
- non-passing official attempts;
- first-attempt passes;
- courses eventually passed on a later attempt.

A retake pass does not double-count credits.

## Semester review status

The semester-level review can be:

- `in_progress`
- `results_pending`
- `retakes_open`
- `complete`
- `incomplete_data`

`complete` means every configured course has a terminal academic outcome: passed or explicitly closed without pass.

A semester that has ended while a course remains active/unresolved is flagged as `incomplete_data`.

## P17 outcome review

P25 reuses the readiness snapshot stored by P24 at result intake.

It classifies official attempts as:

- `aligned`
- `positive_surprise`
- `negative_surprise`
- `mixed`
- `insufficient_evidence`

This is **directional reconciliation only**.

P25 does not:

- subtract readiness from a grade;
- infer a predicted mark;
- calculate pass-probability calibration;
- call the result a P17 forecast error.

Examples:

- fragile/at-risk readiness + pass → positive surprise;
- target-ready/strong readiness + non-pass → negative surprise;
- insufficient P17 evidence → no directional judgment.

## P19/P20 execution review

P25 consumes the existing P20 weekly calibration profile.

The retrospective includes:

- completed committed weeks;
- median weekly adherence;
- capacity signal;
- rebalanced weeks;
- protection-floor sacrifice events;
- per-course allocation signal;
- per-course floor calibration.

This lets the final review distinguish academic outcome problems from workload-estimation problems.

## Evidence-backed retrospective

P25 derives three lists:

### Supported strengths

Examples:

- passed credits;
- later-attempt recovery;
- no negative P17 surprises among sufficiently evidenced attempts;
- weekly capacity broadly matched execution.

### Open concerns

Examples:

- unresolved retake decisions;
- planned retakes;
- courses closed without pass;
- missing/provisional results;
- missing credit configuration;
- negative P17 directional surprises;
- repeatedly oversized weekly commitments;
- repeated protection-floor sacrifices.

### Next-semester actions

Recommendations are derived only when evidence supports them.

Examples:

- resolve retake decisions before allocating new-semester capacity;
- make planned retakes first-class courses from week one;
- audit evidence quality behind negative readiness surprises;
- reduce weekly course envelopes if P20 repeatedly found overcommitment;
- cautiously raise weekly envelopes if actual execution repeatedly exceeded commitments;
- avoid changing capacity if execution was volatile;
- configure missing credits before relying on credit-weighted progress.

If no structural correction is supported, P25 explicitly recommends carrying the existing planning structure forward.

## UI

New route:

`/semester`

The page contains:

- semester review status;
- terminal-course progress;
- passed-credit progress;
- passed / retake / unresolved / closed-without-pass credit totals;
- attempt counts;
- course-by-course academic ledger;
- expandable attempt history;
- P17 ↔ P24 directional review;
- P19/P20 execution review;
- supported strengths;
- unresolved concerns;
- next-semester handoff actions.

Primary navigation includes **Semester**.

## Guardrails

P25 must never:

- count credits more than once because of retakes;
- treat a provisional result as final;
- label a retake-planned course as failed-and-finished;
- leave a completed retake marked merely “planned” after the exam boundary passes;
- invent credits for courses whose credit value is unknown;
- parse arbitrary grade text into GPA without an explicit grading model;
- treat P17 readiness as a predicted exam grade;
- duplicate P24 outcome persistence;
- change P10/P18 allocation authority.
