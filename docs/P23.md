# P23 — Exam-Day Operations, Post-Exam Closure & Cross-Exam Recovery

## Objective

P22 coordinates competing pre-exam strategies. P23 owns the boundary where an exam stops being preparation work and becomes a completed semester event.

P23 answers:

> When exactly should preparation stop, when is an exam allowed to close, what weekly/calendar work becomes obsolete, and how quickly should the remaining exams regain pressure?

## Exam boundary model

P23 derives exam state from the configured course exam timestamp and duration.

No separate completion table is required.

For each configured course:

- `upcoming` — more than 24 hours before the exam;
- `final_window` — within 24 hours but before start;
- `in_progress` — exam start through configured scheduled end;
- `recovery_full` — first 4 hours after scheduled end;
- `recovery_light` — 4–12 hours after scheduled end;
- `post_exam` — after the 12-hour recovery boundary;
- `unconfigured` — no course exam timestamp.

If no exam duration is configured, P23 conservatively assumes 120 minutes for boundary calculations.

## Why P23 does not reuse `study_course_operating_mode` alone

The existing operating-mode view intentionally flips to `post_exam` when `exam_at < now()`.

That is correct for stopping further P9 preparation as soon as the exam starts.

It is not sufficient for closure, because the exam may still be physically in progress.

P23 therefore distinguishes:

- **exam start** → freeze preparation;
- **scheduled exam end** → closure/release becomes eligible.

## Preparation freeze

From exam start onward, P23 removes that course's discretionary candidates from P10:

- ordinary workflow;
- baseline diagnostics;
- cumulative checkpoints;
- P9 exam strategy;
- P14/P16 repair work;
- P19 weekly fallback work.

Explicit P10 commitments are not removed.

This distinction is deliberate:

> obsolete study intent disappears; real obligations do not.

## Retention freeze

P8 review state can still contain due skills for a course whose exam has started.

P23 now removes `post_exam` courses from Today's due-skill queue before the retention queue is built.

This prevents StudyOS from continuing spaced-repetition work for a course whose semester exam has already begun.

Other courses' review work remains unaffected.

## Cross-exam recovery

A completed exam can temporarily constrain exam-strategy work for other courses.

### 0–4 hours after exam end

**Full recovery shield**

- all competing `exam_strategy` candidates are withheld;
- real commitments remain eligible;
- ordinary non-exam work remains under normal P10 authority.

### 4–12 hours after exam end

**Light recovery shield**

- heavy exam actions remain withheld;
- lighter exam actions may return;
- lighter exam actions receive a small −6 P10 priority adjustment.

### After 12 hours

P23 no longer constrains other exams.

P22 resumes ordinary compressed/critical cross-exam coordination.

This is a bounded recovery rule, not a global reduction of P10's capacity settings.

## Closure eligibility

An exam cannot be closed merely because its start time passed.

Closure is available only when:

```text
now >= exam_at + exam_duration_minutes
```

The closure action is idempotent in effect.

If there is no unreleased weekly envelope and no future committed StudyOS calendar block, the course is already operationally closed.

## Calendar cleanup

When an exam is closed, P23 finds future `study_scheduled_blocks` for that course that are still `committed`.

For each obsolete block:

1. delete the linked Google Calendar StudyOS event through the existing P11 cancellation path;
2. mark the StudyOS block cancelled.

Calendar cancellation failures are returned as warnings rather than hiding the rest of the exam closure.

A failed external deletion remains visible for retry because its StudyOS block is not falsely marked cancelled.

## Weekly-envelope release

If the finished course still has unused minutes in the active P19 plan, closure triggers a bounded P19 rolling rebalance.

For the completed course:

```text
new target = credited work, capped by the previous target
```

Therefore unused course minutes are released rather than becoming post-exam study debt.

P23 never expands the weekly course budget.

## Reallocation to remaining exams

If another P22 exam remains within a compressed 21-day runway, P23 applies the release using the P18/P19 `exam_period` objective.

This raises the relative allocation value of the remaining exam runways while still preserving:

- the existing total P19 course budget;
- P20 protection floors;
- current completed work;
- P10 hard daily capacity;
- P11 calendar constraints.

If no compressed exam remains, the existing P19 objective is retained.

The P19 revision records:

```text
last_rebalance_reason = exam_closure:<course_id>
```

so the release is durable and auditable without adding another state table.

## P22 relationship

P22 still owns conflict resolution between active pre-exam strategies.

P23 may temporarily withhold a P22/P9 candidate because:

- another exam is currently in progress;
- the full 0–4h recovery shield is active;
- the candidate is heavy during the 4–12h light-recovery shield.

P23 never changes the P9 method.

When recovery ends, P22 resumes its normal ranking automatically.

## P10 relationship

P10 remains the hard capacity authority.

P23 does not change:

- Normal / Light / Recovery / Intensive budgets;
- max focus-item count;
- retention ceiling;
- commitment priority.

P23 changes only candidate eligibility and a small light-recovery exam priority modifier.

## P11 relationship

P11 remains the clock-placement authority.

P23 can cancel obsolete StudyOS-owned calendar blocks after an exam ends.

It does not modify unrelated external events.

## UI

New route:

`/exam-day`

It shows:

- current exam boundary state;
- configured exam start/end;
- exam duration;
- full/light recovery state;
- active weekly target;
- credited weekly work;
- releasable weekly remainder;
- obsolete future StudyOS calendar-block count;
- explicit closure action;
- upcoming configured exams;
- P23 recovery rules.

Today receives a compact P23 card for:

- final-window exams;
- exams in progress;
- active recovery;
- unresolved post-exam weekly release.

Old resolved post-exam states do not permanently occupy Today.

The exam-day page keeps resolved post-exam entries visible for seven days, while unresolved closures remain visible until fixed.

## Persistence

P23 adds no new table, view, RPC, enum or RLS policy.

Durable effects use existing state:

- `study_courses.exam_at` and `exam_duration_minutes`;
- `study_week_allocations.target_minutes`;
- `study_week_plans.revision / last_rebalanced_at / last_rebalance_reason`;
- `study_scheduled_blocks.status`;
- linked StudyOS Google Calendar events.

## Guardrails

P23 must never:

- mark an exam closed before its scheduled end;
- continue discretionary prep for a course after exam start;
- turn unused exam-week minutes into debt;
- delete unrelated calendar events;
- silently mark a failed calendar deletion as successful;
- reduce or cancel real commitments merely because the exam ended;
- expand P10 or P19 capacity;
- invent a replacement for a blocked P9 method;
- keep heavy exam work active inside post-exam recovery;
- use a new persistence layer when existing P19/P11 state already proves closure.
