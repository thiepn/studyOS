# P32 — Course & Semester Workflow Simplification (first implementation)

## Product problem

The P31 navigation has a clear hierarchy, but a learner entering a course still encounters a generic all-course review route; self-assessment also asked for *pre-reveal* confidence **after** showing the answer. A revealed solution could be silently skipped instead of producing a record. This is both a workflow and evidence-quality defect.

## Delivered

1. **Course-context retrieval:** `/practice?course=<id>` draws eligible due skills **for that course before the review budget is applied**. It uses the same due-skill filters, question-selection ranking, and effective daily review cap as ordinary review. It never substitutes another course or creates a separate daily schedule.
2. **Contextual course work:** Course binders expose an explicit Review due skills action. Teaching-week repair links lead to the corresponding course queue. The weekly checkpoint action enters actual checkpoint mode instead of generic review.
3. **Honest pre-reveal self-assessment:** Confidence 1–5 is selected before revealing a solution; typed mode requires a nonblank attempt, while paper mode is first-class. The selection is displayed read-only after reveal. A give-up can reveal the rubric, but explicitly records an incorrect, zero-credit attempt requiring an error classification.
4. **State integrity:** No "skip instead" path after the answer key is shown. Duplicate session starts are blocked while start is in flight. Creating a finding only clears its form after a confirmed save.
5. **Visual continuity:** New affordances use the restrained P30/P31 academic paper/ink language, not KPI cards or a chatbot panel.

## Invariants

- No schema or policy migration.
- No new grading model, readiness score, calibration formula, exam forecast, capacity ceiling, or weekly-plan authority.
- The course query is a **manual view** into the existing due queue, not additional automatically scheduled reviews.
- StudyOS still records a self-grade; a human must compare worked answers with a trustworthy solution. Free-text or paper answers are not auto-graded.
- Review attempts, session events, and offline retries use the existing persistence interfaces.
- Existing default `/practice` behavior and navigation remain available.
- Historic storage keys and study evidence are not changed.

## Verification

- Unit tests: review-state confidence/lock gating; course-scope behavior before fixed-budget selection.
- CI: behavior tests, TypeScript, Next.js build.
- Human QA still required: keyboard, paper/typed transitions, slow/offline sync, responsive touch, exam workflow and real course data.

## Remaining P32 workflow scope

Course/week/semester actions still span distinct screens. A later P32 follow-up should reduce handoffs on setup, week commitment, and exam execution **without creating competing write authorities**. Do not mark semester-wide workflow simplification complete until real-user scenario walkthroughs verify those routes end to end.
