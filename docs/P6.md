# P6 — Production Deployment, Live Study Drive Connection, Real Course Onboarding & End-to-End Semester Readiness Certification

## Implemented

### Real WS26/27 course onboarding

First-run initialization now creates:

1. Differentialgleichungen
2. Einführung in die Stochastik
3. Theoretische Informatik
4. Algorithmische Mathematik und Programmieren (AMP)
5. Einführung in die Programmierung — retake
6. Grundzüge der Mikroökonomik — retake

Stable internal keys remain unchanged so existing references do not break.

### Readiness center

`/setup` separates readiness into two levels:

- **Infrastructure ready** — server configuration, six courses, dedicated Study Drive connection, and complete Drive folder tree.
- **First week operational** — infrastructure ready plus a real verified resource, extracted skill, and review question.

This avoids treating “deployed” as equivalent to “academic workflow proven.”

### Production liveness

`GET /api/health` is unauthenticated and contains no personal or secret data. It reports only app/version/environment/commit/timestamp and is excluded from the auth proxy.

### Supabase key model

Current Supabase guidance favors publishable + secret keys. StudyOS now prefers `SUPABASE_SECRET_KEY` and keeps `SUPABASE_SERVICE_ROLE_KEY` as a temporary compatibility fallback.

### Compute locality

`vercel.json` pins Vercel Functions to `fra1`. The shared THIEPN Account Supabase project is in EU West (Ireland), so this avoids an accidental U.S. default region for dynamic authenticated requests.

### Privacy

The application emits noindex/nofollow/nocache metadata. It is an authenticated personal study system, not a public content site.

### Migration tracking

P6 is recorded in live Supabase migration history as:

`20261004170959_studyos_p6_real_courses_and_readiness`

The matching SQL is committed under `supabase/migrations/`.

## External activation still required

The connected Vercel plugin currently exposes no teams/projects, so an actual Vercel project cannot be safely provisioned from ChatGPT yet.

Google Drive authorization is also intentionally user-interactive. After deployment the user must:

1. open StudyOS;
2. authenticate through THIEPN Account;
3. open Setup/Resources;
4. select **Connect Google Drive**;
5. choose the dedicated study Google account in Google's account chooser.

The callback stores the encrypted refresh token and creates the full Semester OS folder tree automatically.

## Certification boundary

Before October 12, infrastructure can be certified without fabricated lecture material.

The final end-to-end academic proof should happen on the first real source:

real PDF/source → Drive scan → resource → extraction candidate → approval → skill/question → Practice queue → independent attempt.

Do not manufacture a fake “real-material pass” simply to make the readiness screen green.
