## Actual F11 UX
1. Evidence-first semester onboarding shows the real course roster, Drive, current verified curriculum, retake-baseline diagnostic, and separate formal certification steps. It derives states from the unchanged `evaluateSemesterBootstrap` result, never patches counters or grants ready/certified status.
2. Incomplete courses show safe, course-scoped next actions (course configuration, active-semester Drive setup, course-filtered source desk, fresh baseline) and explanatory blockers. Registered course ≠ verified academic record.
3. Bootstrap action UI requires a deliberate acknowledgement before requesting existing server-side certification; `ready` and the server RPC remain independently authoritative. No automatic certification, no changes to database guardrails.
4. Existing course intake supports real metadata, never demo data; its action is relabeled to avoid asserting newly registered courses are verified. Invalid local exam dates and impossible initial-semester dates receive client feedback before the existing server validation.
5. Course configuration flags a changed or erased exam date and requires explicit review before submitting. Any saved date is still declared course configuration, not proof of the university's published exam date.
6. Historical-prior removal checks HTTP failure, preserves the error and requires a specific confirmation. It calls only the existing scoped delete route. Archives remain read-only academic ledgers and historical evidence never silently carries mastery into the new semester.
7. Archived future Calendar cleanup requires user review of the affected account/events and a specific confirmation before calling the existing archive cleanup route. Existing semester rollover and official outcome guardrails are unchanged.
8. Academic paper/ink editorial layout, accessible page landmarks and links, mobile 1-column course onboarding, 44px touch controls, forced colors, reduced motion and no generic dashboard gradients.
