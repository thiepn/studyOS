# P18 — Semester Scenario Planning, Capacity Trade-offs & Exam-Period Allocation

## Objective

P17 identifies the strategically important course/action. P18 answers the harder allocation question:

> With a fixed amount of study time this week, how should capacity be distributed across courses, what gets protected first, and what must be sacrificed if the week is too small?

P18 is explicitly a planning model. It does **not** predict how many exam points a given number of study minutes will create.

## Capacity source

The default weekly capacity is derived from existing StudyOS constraints.

1. Read the configured default P10 daily planning mode.
2. Multiply its daily budget by seven.
3. If P11 Calendar is connected, cap that nominal budget by the actual seven-day free-window total.

So P18 never assumes that nominal study intent is available when the calendar says otherwise.

The interactive slider may be moved above current Calendar availability for counterfactual analysis. Such a scenario is marked as requiring calendar time to be freed.

## Reserve order

Capacity is reserved in this order:

1. **mandatory commitments due in the next seven days**
2. **retention reserve**
3. **course allocation**

Mandatory commitments use their explicit P10 estimates.

The default retention reserve reuses P10's configured review-to-normal-budget ratio and remains capped by seven times the daily review ceiling. P18 therefore does not invent a second retention policy.

## Course protection floors

Each active course receives a heuristic weekly protection floor before discretionary allocation.

Base floors:

| P17 readiness | Weekly floor |
| --- | ---: |
| insufficient evidence | 45 min |
| at risk | 90 min |
| fragile | 75 min |
| pass-ready | 45 min |
| target-ready | 30 min |
| strong | 20 min |

Runway additions:

| Exam runway | Addition |
| --- | ---: |
| ample / unknown | 0 min |
| workable | +15 min |
| compressed | +45 min |
| urgent | +90 min |
| passed | 0 min |

Other additions:

- declining trajectory: +30 min
- retake course: +15 min

The total floor is capped at 210 minutes/course/week.

These are **scheduler protection floors**, not scientifically estimated hours required to pass.

Post-exam courses receive no active allocation.

## Infeasible weeks

P18 never overbooks the week to make the plan look complete.

Two distinct infeasibilities are surfaced:

### Mandatory deficit

If commitments alone exceed weekly capacity, P18 reports the exact mandatory-work deficit. Course allocation becomes zero.

### Course-protection deficit

If commitments + retention fit but there is not enough remaining capacity to satisfy every course floor, P18 shows:

- total floor shortfall;
- each course's missing minutes;
- explicit sacrifice rank.

The result is intentionally uncomfortable when the real constraint is uncomfortable.

## Allocation algorithm

P18 allocates in 15-minute chunks.

### Pass 1 — protection

It tries to satisfy course floors using marginal protection value.

### Pass 2 — discretionary allocation

Remaining capacity is assigned by marginal value using:

- P17 decision priority;
- P17 highest-action value;
- readiness state;
- exam runway;
- trajectory;
- course credits;
- scenario objective.

After a course's protection floor is satisfied, every extra 15-minute block receives a diminishing-return penalty.

This stops one course from consuming an otherwise balanced week merely because its initial priority is highest.

## Scenario objectives

P18 provides four views over exactly the same capacity.

### Protect passes

Strongly favors at-risk / fragile / evidence-limited courses before spending extra time on already strong courses.

### Balanced

Balances readiness gap, exam runway, trajectory, credits, action value, and diminishing returns.

### Target 80+

Protects pass floors first, then tilts discretionary capacity toward courses below the personal high-performance readiness threshold.

The 80 threshold is the StudyOS readiness target, not a predicted exam score.

### Exam period

Adds stronger pressure for compressed and urgent exam runways while still protecting weak courses.

P9 remains the authority for the actual next exam-preparation action.

## Capacity stress testing

The Scenario page shows:

- 75% of baseline capacity;
- baseline capacity;
- 125% capacity.

This answers:

- what breaks first if the week gets worse?
- how much additional capacity would remove protection shortfalls?
- does extra time mostly rescue a weak course or merely add low-value volume?

The constrained scenario never raises its own capacity to make mandatory work fit.

## Trade-off matrix

For the selected weekly capacity, P18 shows each course's allocation under all four objectives.

This makes the opportunity cost visible. A course receiving less time in one scenario is not silently ignored; the matrix shows where those minutes went instead.

It includes:

- nominal weekly budget;
- actual P11 free time;
- mandatory commitment reserve;
- retention reserve;
- objective selector;
- per-course allocation and floor;

P17 Outlook links directly into P18.

## Architecture

P18 is entirely derived.

Inputs:

- P10 planning settings/capacity;
- P10 commitments;
- P11 seven-day free-window runway;
- P17 course forecasts and next-action values.

No new database table, RLS surface, or persistent scenario state is introduced.

The interactive scenario is browser-local and disposable.

## Guardrails

P18 must never:

- add minutes beyond the selected weekly capacity;
- hide mandatory-work deficits;
- hide course floor shortfalls;
- interpret allocated minutes as predicted score gain;
- allocate post-exam courses;
- override P9's exam-preparation action;
- override P10's daily scheduler;
- turn backlog into extra capacity;
- present counterfactual calendar-over-capacity scenarios as currently feasible.

## Next phase

**P19 — Weekly Commitment, Scenario-to-Plan Translation & Rolling Reallocation**

P19 should convert a selected P18 weekly allocation into a bounded rolling weekly intent: course-level minute envelopes, daily translation through P10/P11, automatic remaining-budget updates after completed sessions, and midweek reallocation when deadlines, missed days, or new evidence materially change the week.
