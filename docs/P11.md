# P11 — Calendar-Aware Scheduling, Lecture/Deadline Sync, Notifications & Weekly Autopilot

## Goal

P10 answers *what* deserves today's bounded study capacity. P11 answers *when it can actually happen*.

The calendar never changes the intellectual priority model. It constrains placement.

## Account boundary

Study Calendar is its own OAuth connection.

It is independent from:

- THIEPN Account authentication;
- Study Drive's selected Google account and refresh token;
- the Google Calendar connector currently available to ChatGPT.

The OAuth flow always uses an account chooser. Only the account explicitly selected inside StudyOS is persisted.

Calendar-specific OAuth environment values may be configured separately. If they are omitted, StudyOS may reuse the same Google OAuth **application credentials** and encryption key as Drive; this does not merge the selected Google accounts or their refresh tokens.

## OAuth scopes

P11 requests only:

- identity: openid, email, profile;
- calendar list read-only;
- calendar event read-only;
- event management on calendars owned by the selected account.

StudyOS does not request full calendar-sharing or ACL administration.

## Calendar selection

On first connection:

- the visible calendar list is recorded;
- only the primary calendar is selected for scheduling constraints;
- the writable primary/owned calendar becomes the target for StudyOS focus blocks when possible.

Additional calendars must be explicitly selected in Today.

This prevents a newly connected account from unexpectedly importing every shared/family/resource calendar into the study planner.

## Cached calendar model

StudyOS stores only the fields needed for scheduling and course context:

- calendar/event IDs;
- summary;
- start/end;
- all-day state;
- status/transparency/event type;
- optional course mapping;
- location/link;
- recurring-series ID;
- sync timestamps.

Refresh tokens are encrypted server-side in a credential table that authenticated/anonymous clients cannot read.

## Free-window engine

The scheduler:

1. constructs the configured local study day in the semester timezone;
2. handles DST when mapping local clock time to UTC;
3. ignores cancelled events;
4. ignores transparent events;
5. expands real busy events by the configured calendar buffer;
6. merges overlapping busy windows;
7. emits only free windows at least as large as the minimum block.

Default rules:

- study day: 08:00–22:00;
- minimum block: 20 minutes;
- calendar buffer: 10 minutes;
- maximum generated block: 90 minutes;
- weekends: enabled;
- Google popup reminder: 10 minutes before.

All values are editable.

## P10 → P11 placement

P11 consumes P10's already-bounded selected plan.

It does **not** reconsider the backlog or expand capacity.

Splittable tasks may span multiple free windows. Non-splittable work such as a timed Altklausur or cumulative checkpoint requires one continuous block. If it cannot fit, it remains unscheduled.

This preserves the P10 invariant:

> Backlog changes priority; it never changes today's capacity.

and adds a second invariant:

> Calendar conflicts change placement; they never create overlap.

## Explicit Calendar writes

Viewing the proposed schedule never writes to Google.

The user must press **Commit today to Google Calendar**.

The server then recomputes the authoritative proposal and creates events from that server-side result. It does not accept arbitrary client-supplied titles/times as the Calendar write contract.

Created blocks:

- are busy events;
- are prefixed with `StudyOS ·`;
- link back to the relevant StudyOS route;
- carry a private StudyOS candidate ID;
- receive the configured Google Calendar popup reminder.

The Calendar event ID and URL are recorded locally.

## Cancellation

A committed block can be cancelled from StudyOS.

Cancellation deletes the Google event first and then records the local block as cancelled. This avoids leaving a local “cancelled” state while the actual Google event is still blocking time.

## Seven-day runway

Today shows a seven-day calendar runway with:

- free study-window minutes;
- number of blocking events;
- number of StudyOS commitments due on that day;
- due-work estimate.

This is a capacity forecast, not a promise to complete every queued task during the week.

## Sync

Sync is explicit after connection/source changes and available through **Sync now**.

The cache records last-sync status/error and surfaces a stale state after six hours. No background cron is required for correctness; StudyOS remains usable when Google is unavailable.

## Notifications

P11 deliberately avoids adding a second browser-push infrastructure.

Actual committed StudyOS focus blocks use native Google Calendar popup reminders. This gives cross-device reminders using the calendar account the user explicitly selected, without service-worker/VAPID complexity or duplicated notification state.

## Pure scheduler verification

Tests cover:

- Europe/Berlin daylight-saving transitions;
- calendar buffers;
- cancelled/transparent event exclusion;
- continuous-block enforcement for timed exams;
- splitting ordinary work across multiple legal windows without crossing busy events.

## Account safety

During P11 implementation, the existing ChatGPT Calendar connector was inspected only to verify that a connector existed. Its event data was not imported into StudyOS and no Calendar writes were made through it because StudyOS must not assume that connector's Google identity is the intended university calendar.


## Lecture and deadline synchronization

Selected Calendar events are deterministically classified from their titles.

Course matching uses existing StudyOS course names/short names. Event roles include lecture, exercise, exam, deadline, StudyOS block, or generic busy time.

Detected lecture/exercise/exam/deadline events appear in Today's synced-course-event list.

Events whose title explicitly signals a deadline (for example `Abgabe`, `deadline`, or `due`) are mirrored into `study_commitments`:

- the Google calendar/event IDs are retained as stable provenance;
- timed deadlines use the event start time;
- all-day deadlines resolve to 23:59 local time on the labelled due date;
- new synced deadlines receive a conservative 45-minute work estimate and priority 3;
- later syncs preserve an existing estimate/priority;
- a completed StudyOS commitment is never reopened merely because the calendar event still exists;
- an explicitly cancelled Google event cancels an open mirrored commitment.

Detected exam events are intentionally **not** allowed to update `study_courses.exam_at` automatically. An exam date affects P8 transition mode and P9 strategy too strongly to trust keyword classification without confirmation.
