# P34 — Mathematical Session Continuity & Week-to-Work Handoff

## Implemented

### Recoverable active mathematical work
- The existing `ReviewSession` keeps a strictly **browser-tab-local** draft while a question is being answered or graded.
- Recoverable state includes the original session/request IDs, question, typed proof/working, conclusion, paper/typed selection, pre-reveal confidence, hint/exposure history, rubric-reveal phase, error classifications, and completed/skipped queue outcomes.
- Session drafts are keyed by study mode, course, question identities, prompts and attached rubrics. Changed questions invalidate earlier drafts rather than showing a newly altered question as already solved.
- Draft parsing refuses corrupt, stale (>24 hours), out-of-order, or invalid-phase content. A session with a revealed rubric never reopens an editable pre-reveal answer.
- The answer and the attempt remain distinct: autosaving a draft **never** records evidence, marks a week completed, or changes mastery. Actual attempts still use the existing idempotent online/offline API.
- `clientRequestId` survives a reload to help avoid double-counted submissions after an uncertain network response.
- Draft saves are debounced to reduce typing lag and flushed on page hide, then removed on successful session completion. They remain confined to the tab; there is no cross-device, server, or permanent-notebook synchronization.
- Failure to access tab storage is explicitly shown; nothing is silently claimed saved.

### More accurate studying time
- Per-question active solving time accumulates only while the document is visible.
- Background tab time, device sleep and time between reloads are excluded rather than misreported as solving time.
- Active duration resumes from the local draft and remains within the attempt API's duration bounds.

### Better mathematical editing
- Added focused structure inserts (proof, cases, derivation, integral, differential equation, probability).
- Optional plain-text reading view distinguishes reasoning and conclusion; it is **not** LaTeX rendering or automatic mathematics checking.
- The existing Unicode notation toolbar, source-grounded rubric comparison, pen-and-paper mode and confidence lock remain intact.
- Editors retain the paper/ink academic style and usable touch targets.

### Lecture-to-practice continuity
- Every course teaching week shows a four-stage, read-only progress rail from authoritative milestone timestamps.
- Its Practice button opens `/practice?mode=week&course=<id>&week=<number>`: a bounded question set for **skills first introduced that week**, not a generic due queue or the cumulative checkpoint.
- Existing course-week checkpoint remains cumulative. Completing new-week practice alone does not falsify exercise sheet or checkpoint completion.
- Returning from week practice/checkpoint opens the exact originating teaching week through a hash link, even when it is not the featured card.
- Week practice may be empty when material is not yet approved; empty states stay honest.

### Scope and limitations
- No new database schema/migration; the authoritative attempts, sessions, skills, milestone RPCs and materials pipeline remain unchanged.
- Source and answers are not backed up as cross-device drafts. Browser-tab storage is a convenience, not durable university-notes storage.
- Correctness is still source-verified self-assessment, not automated proof checking.
- The reading preview is formatted plain text. Full reliable LaTeX/MathML rendering and hand-drawn equations are not implemented here.
- Production browser/device, reload during offline submission, accessibility and real-student workflows require live qualification.
