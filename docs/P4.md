# P4 — Automated Drive Intake, Academic Ingestion Pipeline & Weekly Course Workflow

## Status

Implemented on 2026-10-04.

P4 automates the transport and control plane around course material without silently introducing a paid LLM dependency.

## Delivered

- Separate Google Drive OAuth integration owned by StudyOS.
- Google account chooser: StudyOS can use a different Google account from THIEPN Account and from ChatGPT connectors.
- Server-side refresh-token storage encrypted with AES-256-GCM.
- Disconnect and switch-account flows.
- StudyOS-owned Drive tree creation:
  - Semester OS
  - WS26-27
  - 00_INBOX
  - six course folders
  - 00_COURSE / 01_WEEKS / 90_ALTKLAUSUREN / 91_SCRIPT / 92_REFERENCE / 99_SYSTEM
- Drive tree scanning and deterministic file classification by:
  - course
  - document type
  - teaching week
  - filename/folder context
- Deduplicated Drive intake ledger.
- Resource/version deduplication and content-hash path for changed files.
- Structured extraction-candidate contract.
- Candidate validation/conflict detection:
  - low extraction confidence
  - missing/duplicate stable keys
  - title conflicts
  - missing questions
  - missing prompts
- Blocking validation issues prevent approval.
- Human approval remains mandatory before extracted material modifies the active study map.
- Weekly course-health projection:
  - empty
  - needs_processing
  - source_only
  - learning
  - fragile
  - retained
- Courses UI exposes weekly health.
- Resources UI exposes Drive account, scan status, intake queue, candidate approvals, and registered source archive.

## Intentional boundary

Drive discovery and course/week/type classification are automatic.

Semantic extraction of mathematical/economic/programming content into topics, atomic skills, rubrics, hints, and questions is represented by a processor interface and candidate RPC, but P4 does **not** silently call a paid LLM API. A future processor can be connected to this boundary without changing the approval, provenance, or review architecture.

This is intentional because the system should not create recurring API costs or make AI-generated academic content authoritative without an explicit product decision.

## Drive account isolation

The StudyOS Google Drive connection is independent from THIEPN Account authentication.

Changing the StudyOS Drive account:
1. replaces the encrypted StudyOS refresh credential;
2. clears stored StudyOS folder references;
3. creates a fresh Semester OS tree in the newly selected account;
4. does not move or delete files in the previous account.

The old ChatGPT-connected Drive account is not part of the StudyOS production architecture.

## Backend status

The live backend is in the existing THIEPN Account Supabase project under the `study_*` namespace.

P0–P4 DDL was applied directly to that live project during development. The repository contains the typed client contract, but a clean-room migration baseline for provisioning a brand-new Supabase project has not yet been generated. Do not claim that cloning this repository alone recreates the backend.
