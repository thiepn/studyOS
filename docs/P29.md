# P29 — Product Consolidation & Architecture Cleanup

## Objective

P29 stops adding learning intelligence and consolidates StudyOS into a coherent product surface.

The study engine through P28 remains authoritative. P29 changes presentation, route responsibility, naming, failure handling, and product organization only.

## Product naming

- User-facing product name: **StudyOS**.
- New Study Drive roots use **StudyOS**.
- Existing legacy **Semester OS** Drive roots remain supported and are not destructively migrated.
- Semester labels come from the active semester record; no current UI should depend on a hard-coded WS26/27 identity.
- A fresh account creates its first semester explicitly; no fixed semester or example roster is inserted.

## Primary navigation

Only four study destinations are first-class plus one contextual menu:

1. **Today** — execute the current bounded plan.
2. **Study** — retrieval practice, calibration, repair, and timed papers.
3. **Courses** — course/week workflow and source-linked academic work.
4. **Progress** — current evidence, course risk, retention, drift, intervention, and longitudinal diagnostics.
5. **More** — infrequent planning, exam, semester, material, and system workflows.

Advanced routes remain available but are not treated as equal everyday destinations.

## Route responsibility map

### Primary workflow

| Route | Responsibility |
| --- | --- |
| `/` | Current-day execution authority. Shows the ordered plan and only exceptional signals capable of changing it. |
| `/practice` | Active study workspace. Default entry begins with due retrieval; calibration and exam modes are secondary. |
| `/courses` | Course index and entry into course-specific academic workflow. |
| `/progress` | Current evidence and diagnosis. Explains what is strong, weak, drifting, or historically recurring. |

### Course context

| Route | Responsibility |
| --- | --- |
| `/courses/[id]` | Operational course binder: teaching weeks, material, exercises, findings, exam sources. |
| `/diagnostics/[courseId]` | Fresh baseline/diagnostic work, especially for retakes. |
| `/strategy` | Controlled method experimentation only when ordinary repair is insufficient. |
| `/practice/exam/[id]` | Timed, closed-book paper simulation and grading workflow. |

### Planning context

| Route | Responsibility |
| --- | --- |
| `/week` | The current committed weekly plan and execution envelope. |
| `/scenarios` | Compare feasible allocations before committing a week; never a second active plan. |
| `/handoff` | Close a completed week and prepare the next one from current evidence. |
| `/outlook` | Strategic semester readiness and next-action ordering; does not schedule the day. |
| `/quality` | Advanced review of whether planning heuristics matched actual execution; does not change mastery. |

### Material context

| Route | Responsibility |
| --- | --- |
| `/resources` | Drive discovery, intake, source processing, validation, provenance, and approval. |

### Exam lifecycle

| Route | Responsibility |
| --- | --- |
| `/exam-command` | Multi-exam prioritization and conflict/runway planning. |
| `/exam-day` | Final-window, in-progress, closure, and recovery boundaries. |
| `/exam-results` | Official result intake, reconciliation, and retake decisions. |

### Semester lifecycle

| Route | Responsibility |
| --- | --- |
| `/semester/bootstrap` | New-semester setup/readiness: roster, Drive tree, curriculum anchor, retake baseline, prior context. |
| `/semester` | End-of-semester academic and execution review. |
| `/semesters` | Semester history index. |
| `/semester/archive/[semesterId]` | Read-only archived semester evidence. |
| `/semester/rollover` | Archive current semester and create the next active workspace. |

### System

| Route | Responsibility |
| --- | --- |
| `/setup` | Integration and infrastructure readiness. |
| `/login` | THIEPN Account authentication only. |

## Consolidation decisions

- No route is deleted in P29 because each still owns a distinct state transition or evidence view.
- Duplicate *summaries* may appear contextually, but only one route owns each mutation/authority.
- Progress diagnoses evidence; Outlook prioritizes strategic action; Quality audits the planner.
- Scenarios explore; Week commits/executes; Handoff closes and regenerates.
- Exam planning prioritizes; Exam Day enforces temporal boundaries; Results records official outcomes.
- Semester setup creates a usable workspace; Semester review closes it; History/archive preserve it.

## Language contract

Normal user-facing UI must not require knowledge of P-phase numbers.

Engineering phase IDs remain valid in:
- repository history,
- docs/P*.md,
- migrations,
- tests,
- audit notes and internal stored labels when needed for compatibility.

They should not appear as the primary explanation of a feature to the student.

## Route-state handling

P29 adds global:
- `loading.tsx` — quiet StudyOS loading state,
- `error.tsx` — safe retry path that explicitly preserves saved study data,
- `not-found.tsx` — useful recovery to Today/Courses.

These are fallback boundaries. Individual workflows may still provide richer local empty/error states.

## Drive compatibility

New root provisioning prefers `StudyOS`.

If an existing top-level `Semester OS` root is present, it is reused rather than creating a duplicate or performing a destructive rename. Existing stored root IDs continue to be authoritative.

## Invariants

P29 must not:
- restore historical mastery,
- alter mastery-credit rules,
- change readiness calculations,
- change planning-capacity ceilings,
- change weekly/exam authority,
- reinterpret exam outcomes,
- add a second source of truth,
- remove auditability from the study lifecycle.

## Qualification

P29 is complete when:

1. StudyOS naming is consistent in metadata/login/current UI.
2. Core and advanced workflow screens no longer depend on phase-number jargon.
3. New Drive roots use the StudyOS name while legacy roots remain compatible.
4. Every existing route has an explicit responsibility and no route is accidentally acting as a second authority.
5. Global loading/error/not-found handling exists.
6. behavior tests pass.
7. TypeScript passes.
8. Next.js production build passes.
