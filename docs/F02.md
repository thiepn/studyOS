# F02 — Account Sign-in Reliability

## Scope
Stacked on the qualified F01 exact head. Existing THIEPN Account / Supabase infrastructure is retained, and no Google Cloud account or OAuth client is recreated.

## Corrected flows
- Existing authenticated sessions entering `/login?next=...` return to the validated deep link, not unconditionally to Today.
- Google start/callback errors are classified into user-safe, retryable states without exposing raw provider responses or tokens.
- Successful PKCE code exchange is checked for verified session claims before redirecting to a private destination.
- Same-origin POST-based StudyOS-only sign-out is added, with an authenticated Account page; Drive/Calendar authorizations and files remain intact.
- The sign-in view uses a two-column, editorial academic layout on desktop, single-column on mobile, accessible alert/status treatment, and clear separation between THIEPN identity and linked Study services.
- No passwords, refresh tokens, provider access tokens, or private Drive IDs are stored in client-side UI or repository.

## Qualification
Require Node unit tests, TypeScript, Next.js build, browser Supabase config check and real built-server anonymous acceptance on the exact F02 head. A protected-browser sign-in, cookie persistence and Google OAuth return on the live canonical domain still require a real browser/provider authorization; do not claim they were performed if absent.

## F03
Account experience, Google account identity differentiation, consent status, reauthorization UX, and cross-account switch/revocation/recovery hardening.
