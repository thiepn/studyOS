# P7 — Source-Grounded Academic Processing, Course Master Maps & Review Generation

## Goal

P7 closes the semantic gap between archived university files and the review engine without making StudyOS dependent on a paid LLM API.

The operating contract is:

```text
source file
→ processing brief
→ ChatGPT-assisted/manual candidate JSON
→ database validation
→ explicit user approval
→ Course Master Map
→ review queue
```

## Source-grounded candidate contract

Every extracted skill and every generated/official question must point to the source through at least one of:

- `page_start`
- `page_end`
- `section_label`

Every question must include an `answer_key_or_rubric`.

Candidates are constrained to prevent review-card explosion:

- maximum 30 topics per source
- maximum 120 skills per source
- maximum 400 questions per source
- maximum 12 questions for one skill
- warnings start much earlier (12 topics, 80 questions, 6 questions/skill)

Stable keys must be lowercase machine-stable identifiers. Existing keys are included in the processing packet so a processor can reuse the course taxonomy rather than generating synonyms.

## Course-specific processing profiles

The processing brief is adapted to the real course:

- DGL: theorem assumptions, method recognition, procedures, proofs, calculations, transfer
- Stochastik: probability-model recognition, distributions, derivations, interpretation, transfer
- Theoretische Informatik: formal definitions, constructions, proofs, reductions, correctness
- AMP: mathematical formulation, algorithms, derivation, implementation, complexity, debugging
- Einführung in die Programmierung: trace, implement, debug, complexity, transfer
- Mikroökonomik: concept → assumptions → graph → derivation → interpretation → changed assumption

Exam-like questions should not reveal the method when method selection is part of competence.

## Reprocessing corrected material

Accepting a replacement version of a source now:

1. retires active official/generated questions sourced from the previous version;
2. refreshes resource→skill provenance;
3. reuses existing course topic/skill identities when stable keys match;
4. creates only the new canonical questions.

This prevents old and corrected questions from both remaining active.

## Course Master Map

Each course page now has a source-derived Master Map with:

- topics and source weeks
- atomic skills
- mastery state distribution
- durable percentage
- unresolved errors
- source-resource count and titles
- skill evidence requirements and exam importance

The Master Map is reconstructed from accepted database state, not from chat history.

## Processing queue UI

Queued ingestion runs now expose:

- a course-specific processing brief
- one-click copy
- a JSON import box
- backend validation
- validation details
- existing explicit acceptance/rejection

No automatic paid model call is introduced.

## Backend verification

A rollback integration test confirmed:

- unanchored candidate → blocked
- source-grounded candidate → zero blocking issues
- first acceptance → topic + skill + question created
- corrected source reprocessing → old question retired
- one new active question remains
- Course Master Map updates successfully
