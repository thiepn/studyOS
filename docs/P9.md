# P9 — Altklausur Intelligence, Exam Blueprint, Timed Simulation & Exam-Strategy Engine

## Goal

P9 converts accepted past papers into a conservative exam-preparation system. Historical exams inform preparation, but never define the syllabus.

## Source model

Past exam PDFs remain Drive resources. Once an `exam` ingestion candidate is accepted:

1. reusable topics/skills are reconciled with the Course Master Map;
2. every numbered/sub-numbered exam problem is stored in `study_exam_questions`;
3. every exam problem is also represented as an `exam_problem` question with `exam` evidence dimension;
4. source pages and points remain attached to the original paper;
5. the paper receives a stable key so later solution PDFs can target it exactly.

An `exam_solution` source does not create a parallel paper. It targets an existing `exam_stable_key` and upgrades grading rubrics.

## Solution authority

A rubric has one of four states:

- `missing`: no answer available;
- `unverified`: answer/rubric exists but is not trusted as authoritative;
- `verified`: checked sufficiently for mastery evidence;
- `official`: official course/solution source.

Raw self-grading is useful for diagnostics. Only `verified` or `official` grades can create mastery-creditable exam attempts.

## Syllabus drift

Each paper has `syllabus_relevance` from 0 to 1.

Recency is applied separately. An old exam is not automatically obsolete; a recent exam is not automatically representative. The effective historical weight is:

```text
syllabus relevance × recency weight
```

This allows an old but still structurally relevant paper to remain useful and lets a paper from an obsolete syllabus be down-weighted without deleting its evidence.

## Exam Blueprint

Every current Course Master Map topic remains present, including topics that never appeared in the mapped past papers.

Blueprint priority is explainable:

- up to 35 points from weighted historical occurrence / point share;
- up to 20 from course-level exam importance;
- up to 25 from current exam-readiness gap;
- up to 20 from certified timed-simulation weakness.

This prevents historical frequency from assigning a syllabus topic zero importance.

Historical confidence is intentionally conservative:

- no papers → none;
- 1 weighted paper → low;
- 2–3 → medium;
- 4+ → high.

## Timed simulation

A simulation snapshots one accepted paper into immutable simulation items.

During solving:

- one global exam timer runs;
- questions can be navigated;
- responses and per-question time are persisted;
- no solution/rubric is returned to the client.

After submission:

- rubrics become visible;
- each question receives points;
- lost points require an error diagnosis;
- raw and verified scores are kept separately.

Only a verified/official item calls the ordinary attempt engine and therefore updates mastery/review state.

## Strategy engine

The course exam strategy combines:

- P8 operating mode and days to exam;
- amount/confidence of mapped past-paper evidence;
- verified solution coverage;
- latest timed-paper evidence;
- Exam Blueprint priorities.

Possible next actions include:

- process past exams;
- add another exam before trusting frequency;
- maintain the blueprint during normal semester mode;
- run a baseline timed paper;
- verify solutions;
- repair weaknesses;
- mixed exam practice;
- run another timed paper.

For a configured exam duration, StudyOS reserves roughly:

- 75% for the first pass;
- 10% for final checking;
- the remainder for returning to marked/skipped problems.

Working minutes per point excludes the final-check reserve.

## Verified integration contract

A rollback integration test exercised the complete flow:

```text
exam candidate
→ zero blocking P9 validation
→ accepted paper
→ two numbered questions linked to course skill
→ official solution candidate
→ both rubrics become official
→ paper becomes simulation-ready
→ 20-point timed simulation
→ 15/20 raw score = 75%
→ 100% verified grading coverage
→ two exam-dimension attempts recorded
→ blueprint topic frequency / point share = 100%
→ strategy confidence remains LOW with only one paper
→ next action = add_exam_evidence
```

That final behavior is deliberate: StudyOS refuses to call one old exam a reliable frequency distribution.

All synthetic integration data was rolled back.
